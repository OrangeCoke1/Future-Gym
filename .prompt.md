# Task: Add Vue Router, make App.vue an empty container (App → AppLayout → route views), rewrite the rules

> Redone on top of main a6f1854 (camera window, rigged models, lenient squats): the camera settings that main
> applies at startup in App.vue (`setCamTune`, `setHands`, `setPoseModel`, `setFitLenient`, `setBody`,
> `stickman.setCamLead`) move into `useAppSetup()` with the rest of the app-wide setup.

## Goal
Prepare for future pages. `src/App.vue` currently does app bootstrap, the whole page layout and drawer state.
After this task:
- `App.vue` runs app-level setup and renders `<RouterView />`.
- `router/index.js` defines the routes; the current screen is the `training` route at `/`.
- `layouts/AppLayout.vue` is the shell shared by pages (top bar, settings drawer).
- `views/TrainingView.vue` is the current screen; its three regions live in `views/training/`.
Pure restructuring for the user: rendered DOM inside `#app`, classes, styles and behaviour stay the same.

## Decisions
- **vue-router 5.4.0 (latest stable, user's choice)**. It declares optional peers `vite ^7.3 || ^8` and
  `pinia ^3.0.4 || ^4.0.2`; with the current vite 6.4.4 / pinia 2.3.1, `npm install --dry-run` fails with
  ERESOLVE. So the same change upgrades the peers to the smallest compatible majors (dry-run resolves):
  | package | now | after |
  | --- | --- | --- |
  | vue-router | – | 5.4.0 |
  | pinia | 2.3.1 | 3.0.4 |
  | vite | 6.4.4 | 7.3.7 |
  | @vitejs/plugin-vue | 5.2.4 | 6.0.10 (5.x does not support vite 7) |
  All pinned exactly like the other deps; no `--force` / `--legacy-peer-deps`. Run `npm audit` after install.
  Alternative (all latest: pinia 4.1.0 + vite 8.3.5, also resolves) is not chosen: vite 8 switches the bundler to
  Rolldown, so `vite.config.js` (`build.rollupOptions.output.manualChunks`, `optimizeDeps`) would need rework.
- **Impact of the upgrades**:
  - vite 7 / plugin-vue 6 need **Node ^20.19 or >=22.12** (local: 22.22.2). This also applies to `start.bat`,
    which builds `dist/` with Node; document it in README.md.
  - vite 7 default build target becomes "baseline widely available" (Chrome/Edge 107+, Safari 16+); the app
    already requires recent Chrome/Edge for WebGL + MediaPipe.
  - pinia 3 drops Vue 2 support and deprecated APIs; the stores use `defineStore` with setup syntax only — check
    `stores/*.js` compile and behave the same.
  - vue-router 5 exports the same runtime API as 4 (`createRouter`, `createWebHashHistory`, `RouterView`,
    `isReady` confirmed in 5.4.0 typings); its file-based routing plugin (`vue-router/vite`) is not used.
- **Hash history (`createWebHashHistory`)**. `serve.ps1` has no SPA fallback (unknown paths → 404), so with web
  history a refresh on any future page would break under `start.bat`. Hash URLs need no server change and do not
  collide with the real `/poster/` folder. Visible effect: the address becomes `http://localhost:8000/#/`.
- **Mount after `router.isReady()`** in `main.js`; RouterView renders asynchronously on the first navigation.
- **`useLayoutVars()` moves from App to `TrainingView`**: it applies stored card sizes to `[data-rz]` elements in
  `onMounted`; those elements belong to the training page, and running it in the page re-applies sizes whenever
  the page is (re)mounted.
- **Naming**: `views/` = one component per route, named `XxxView`. Page-only parts go in `views/<page>/` and are
  named `XxxPanel` (`LeftPanel`, `CenterPanel`, `RightPanel`); `components/` keeps reusable/shared components.
  `components/StageView.vue` (the canvas) keeps its name. All names are multi-word for
  `vue/multi-word-component-names`.

## Constraints (why the DOM must not change)
- `.app` is a CSS grid (`styles/layout.css`); direct children are placed by class (`.top`, `.side.l`, `.side.r`,
  `.stage`, `.app>.split.col`, `.bottom`). `AppLayout` renders `<div class="app">` with `TopBar` and
  `<RouterView />`; `TrainingView` is a **multi-root (fragment)** component so its parts stay direct children of
  `.app`. Each panel uses the original element as its single root — no wrapper div.
- `composables/useLayout.js` queries `.app`, `.side.l`, `.side.r`, `[data-rz]` via `document.querySelector`.
- `SettingsDrawer` stays a sibling of `.app` (AppLayout keeps a multi-root template).
- `--cl` / `--cr` stay on `.app` (in AppLayout) because the grid reads them there.

## Steps
1. **Baseline**: `npm install` in `stickman-preview/` (node_modules missing in this worktree), `npm run build`,
   `npm run preview`, save `chromium --headless --dump-dom http://localhost:8000/` (after mount) to the

2. **Dependencies**: `npm install --save-exact vue-router@5.4.0 pinia@3.0.4` and

3. **`src/router/index.js`** (new): `createRouter({ history: createWebHashHistory(), routes })` with
   `{ path: '/', component: AppLayout, children: [{ path: '', name: 'training', component: TrainingView }] }`
   and a catch-all `{ path: '/:pathMatch(.*)*', redirect: '/' }`. JSDoc note: future pages are added as children
   of AppLayout and lazy-loaded with `() => import(...)`; the default page stays a static import.
4. **`src/main.js`**: `.use(router)`, mount inside `router.isReady().then(...)`.
5. **`src/composables/useAppSetup.js`** (new): `useAppSetup()` with JSDoc; moves from App.vue
   `provideEngine({ profile, opts, camView })`, `useDocumentLang()`, `window.stickman = { setHeartRate }`
   (same comment). The engine is provided at App level so it outlives page navigation.
6. **`src/App.vue`**: `useAppSetup()` + `<RouterView />`.
7. **`src/layouts/AppLayout.vue`** (new): `<div class="app" :style="--cl/--cr">` with `TopBar` and `<RouterView />`;
   `<SettingsDrawer v-model:open>` as a sibling. Owns `drawerOpen`, the `topBar` ref and the focus-return watch.

## Known follow-up (not in this task)
- `engine.attach()` creates a new stage (WebGL context, GLB parse) on every StageView mount and nothing disposes
  the old one. Harmless with one page; once a second page exists, navigating away and back would leak a WebGL
  context. Needs an `engine.detach()` called from StageView's `onBeforeUnmount` (or `<KeepAlive>` for the page).
