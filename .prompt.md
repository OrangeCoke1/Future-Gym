# Task: Camera-following tuning controls in 面板 (drawer)

User ask: "能不能在面板里做一个调整的窗口" — after the lag fix (PR #2: One Euro retune + velocity prediction), let the user
tune the jitter / latency trade-off from the UI instead of the console (`stickman.setCamLead`).

## Analysis
- Today the One Euro parameters are hard-coded defaults of `oneEuro()` in `src/pose/camera.js` (minCut 2, beta 8, dCut 2),
  each joint/axis has its own closure created on first sight; prediction lead is `S.camLead` (engine, default 0.08 s).
- The drawer (`SettingsDrawer.vue`) holds sections `DisplayOptions`, `ProfileForm`, `SessionLog`, `DataNotes`.
  A new section fits there; settings persist through the settings store + `utils/storage.js` (sanitised reads).
- PR #1 (floating camera window, unmerged) also edits `stores/settings.js` (adds `camWin`). Our change adds one more
  field there, so whichever merges second gets a trivial conflict in the store's return line. Keep the edit minimal.

## Plan
1. `src/pose/camera.js`
   - Add an exported tuning object shape `CamTune = { minCut, beta, lead }` (JSDoc typedef) and `CAM_TUNE_DEFAULT = { minCut: 2, beta: 8, lead: 80 }`
     (lead in ms), plus ranges `CAM_TUNE_RANGE` (minCut 0.5–5 Hz, beta 0–20, lead 0–150 ms).
   - `oneEuro` reads `minCut` / `beta` from a tuning object passed by reference (`cam.tune`) at each call, so changes apply
     live without recreating filters. `createCamPose` gets `tune` (copy of defaults).
2. `src/engine/engine.js`
   - Replace `setCamLead(ms)` by `setCamTune(partial)`: validates each field with the ranges (non-finite → keep current),
     writes `camera.pose.tune`; `S.camLead` derived from `tune.lead / 1000`. Keep `stickman.setCamLead(ms)` working as a
     thin wrapper (CLAUDE.md documents it).
3. `src/stores/settings.js`
   - `camTune` reactive, loaded from `stick.camTune` with a sanitiser (numIn per field, defaults on bad data), saved on change.
4. New `src/components/drawer/CameraTuning.vue` (<script setup>, < 100 lines), section "摄像头跟随":
   - Three presets as a segmented control: 稳定 (minCut 1.2, beta 4, lead 40) / 平衡 (defaults) / 跟手 (minCut 3, beta 12, lead 120).
   - Three range sliders with live value read-outs: 防抖强度 (minCut, shown inverted as "smooth ↔ responsive"),
     速度响应 (beta), 预测提前量 (lead ms). Each change → `settings.camTune` + `engine.setCamTune`.
   - "恢复默认" button. One-line hint: "站着不动时抖 → 调低灵敏；动起来时拖后/超前 → 调整预测".
   - Glass styling via existing drawer classes (`row`, `seg`, `note`, `btn`); add a few rules to the drawer stylesheet
     for the slider only if needed.
   - Mount it in `SettingsDrawer.vue` after `DisplayOptions`. Apply the persisted tune once at startup (in App.vue next to
     `provideEngine`, or in the component's setup via `engine.setCamTune(settings.camTune)` in App).
5. i18n: add ja/en entries in `src/i18n/messages.js` for every new Chinese string.
6. Docs: CLAUDE.md line about `setCamLead` → mention the panel section; `.dev_log` entry.
7. Checks: `npm run lint`, `npm run build`, headless smoke test (drawer opens, sliders change `camera.pose.tune`, no console errors),
   offline filter simulation re-run for the three presets (lag / still-jitter numbers into the PR body).
8. Commit on `claude/project-thread-c1dndn` (restarted from main since PR #2 merged), open a PR; merge on the user's word,
   then rebuild the Mac/Windows preview zip (with PR #1 included as before if still unmerged).
