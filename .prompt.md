# Task: Refactor `stickman-preview` in place into a Vue 3 (JavaScript) project, split by feature modules

Status: PLAN ONLY — waiting for `execute`. Execute **one phase per trigger** (e.g. `execute phase 0`).

## 0. Decisions (confirmed by user)

1. Convert `stickman-preview/` **in place** (it becomes the Vite project root).
2. **No** Element Plus / glassmorphism restyle — pure refactor, visual & behavioural parity.
3. **No** Vitest / automated tests — verification is `npm run build` + ESLint + manual side-by-side check in the browser.
4. `poster/` **stays where it is, unchanged** (files, bake scripts, URLs).

## 1. Current state (analysis)

- `index.html` (~2700 lines) = CSS (L10–305) + markup (L306–540) + one IIFE script (L541–2708).
  Script sections (by `=====` banners): math (543) · body/skeleton (563) · actions `ACT` (594) · solve (669) ·
  DOM/state + `store` (737) · i18n `I18N` (743) · layout splits / drawer / rep counting (~860–1097) ·
  camera pose (1098) · `FIT` recognition (1277) · metrics/bio/water (1446) · charts + thermal (1556) ·
  Three.js renderer: SDF body, GLB parse + CPU skinning, particles, moiré, fist/grip (1756) · overlay (2564) · `loop` (2613) · language apply (2683).
- All state is closure-local `let` variables shared across sections; ~57 DOM ids, ~29 listeners, per-frame mutation.
- Vendored: `three.min.js` (r149, global `THREE`), `mediapipe/` (tasks-vision 0.10.14 ESM + wasm + `.task`), `male_body.glb`.
- `poster/` depends on URLs `/three.min.js` and `/male_body.glb` (bake pages use `../three.min.js`, `../male_body.glb`);
  `bake-figure-a.ps1` loads `http://localhost:8000/poster/...`.
- Node 22 / npm 10 available.

## 2. Key risks & mitigations

1. **Per-frame performance**: skeleton solve, CPU skinning (~42k verts, ~22k particles) and canvas drawing run at 60 fps.
   Keep them as plain JS modules; Three objects wrapped with `markRaw`; Vue renders only the shell. Read-outs are pushed
   into reactive state at the existing throttle (0.25 s `uiTick`); smoothed bars written once per frame to a small reactive object at most.
2. **Behaviour parity**: no visual or rule changes. `FIT` is moved **verbatim** into `src/pose/fit.js`
   (must stay a line-by-line port of `media-pipe-practice-main/apps/web/src`).
3. **App is broken mid-migration** (in-place conversion): keep the original page as `legacy.html` (served unchanged by Vite)
   until Phase 6, as the working version and the side-by-side reference. Deleted in Phase 6.
4. **Asset URLs**: move `male_body.glb`, `three.min.js`, `mediapipe/wasm/*`, `mediapipe/pose_landmarker_full.task` into `public/`
   → served at the same URLs, so `poster/` and `legacy.html` keep working without edits. Vite `server.port = 8000` so the bake script still works.
5. **Posters in build**: `poster/` is not a Vite entry (classic scripts); a tiny plugin in `vite.config.js` copies `poster/` to `dist/poster/` on build.
6. **Deps**: `three@0.149.0` (matches r149 shader/API code), `@mediapipe/tasks-vision@0.10.14` (wasm + model still loaded from `public/mediapipe/`, offline-capable), `vue`, `pinia`.
7. **Run scripts**: the page now needs a build. `serve.ps1` gets a `-Root` param defaulting to `dist/`; `start.bat` serves `dist/`.
   Machines without Node need a prebuilt `dist/` (not committed by default). Dev: `npm run dev`.
8. **localStorage**: keep existing `stick.*` keys (water log, profile, layout, lang, camView) and validate on read with guard functions + safe defaults (GLOBAL_RULES §4).
9. **i18n**: keep the `I18N` table keyed by Chinese source text; replace the TreeWalker trick with `useI18n()` (`t()` reactive on `lang`). No vue-i18n.
