## A. No DOM lookups in app code
Today five lookups find elements by selector:
- `composables/useLayout.js`: `.app`, `.side.l`, `.side.r`, `[data-rz]`;
- `components/stage/CamPreview.vue`: `.stage`.

Replace them with template refs shared through provide / inject.

- **`useLayout.js`:**
  - `provideLayout()` (called in `AppLayout.vue`) creates and provides `{ el: { app, cl, cr, stage }, cards }`:
    - each `el` entry is a `shallowRef(null)`;
    - `cards` maps a `data-rz` key to its `shallowRef`;
    - `provideLayout()` returns the context, and AppLayout binds `ref` on `.app` to `el.app`.
  - `layoutRef(name)` returns the shared ref for `'cl'` / `'cr'` / `'stage'`, to bind with `ref="…"`:
    - `LeftPanel` → `cl`, `RightPanel` → `cr`, `StageView` → `stage`.
  - `useCard(key)` returns `{ el, style }`:
    - `el` is registered in `cards` while mounted;
    - `style` is a computed `{ '--g': layout.g[key] }`, or `null` when the key has no stored value.
    - The card binds `ref="el"` and `:style="style"` on its root and keeps `data-rz` (the CSS uses it). This replaces `useLayoutVars()`, which wrote `--g` by `querySelectorAll`, so `TrainingView` no longer calls it.
    - Cards: `BalanceCard` (bal), `HydrationCard` (water), `SweatCard` (sweat), `LoadCard` (load), `HeartRateCard` (hr), `EnergyCard` (kcal), and the `.pair` div in `LeftPanel` (pair).
  - `useSplit()` reads its elements from the injected context instead of `querySelector`. The measurements and maths are unchanged.
- **`CamPreview.vue`:** `place()` uses the injected `stage` ref.
- **Kept, because these are page-level, outside the Vue tree:**
  - `document.body` (resize cursor in `SplitHandle`);
  - `document.documentElement.lang` (`useI18n`);
  - `documentElement.clientWidth/Height` (viewport size in `useFloatWin`).
- **Rule (GLOBAL_RULES §4):** in app code, reach elements only through template refs (shared via provide / inject when another component needs them); never `querySelector` / `getElementById` / class or attribute lookups. Only `document.body` / `document.documentElement` may be used, for page-level state. The Project Structure bullet that says "useLayout.js queries .app …" is rewritten accordingly.

## D. `start.bat` rebuilds a stale `dist/`
- The logic moves into a new `build-if-stale.ps1`. PowerShell is easier to get right than batch, and `serve.ps1` already needs it. The syntax must work in Windows PowerShell 5.1 as well: no `?:`, `??` or `&&`.
- **When to build:** when `dist\index.html` is missing, or is older than the newest file in `src\`, `public\`, `poster\`, `index.html`, `vite.config.js`, `package.json` or `package-lock.json`. A `git pull` stamps changed files with the current time.
- **Install:** with npm found, run `npm ci` only when `node_modules\.package-lock.json` is missing or older than `package-lock.json`. An up-to-date machine needs no network, which matters for offline exhibition PCs. Then run `npm run build`.
- **Fallbacks:**
  - No npm: if `dist\` exists, warn that it is older than the sources and serve it; otherwise print the "build on a machine with Node.js and copy dist\" message.
  - Install or build fails: keep the old `dist\` if there is one, warn, and serve it.
- **`start.bat`:** calls `build-if-stale.ps1`, then `serve.ps1` as before when `dist\index.html` exists, then `pause`.
- **Test:** PowerShell 7 for Linux, downloaded into the scratchpad, with temporary folders, touched timestamps and a stub `npm`. Cases: up to date, stale sources, stale lockfile, no npm, failing build. This cannot exercise `cmd.exe` or Windows PowerShell 5.1 itself, and I will say so.
