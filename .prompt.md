## Steps

### 1. Render loop survives errors (`src/engine/engine.js`)
- `frame(now)` schedules the next frame **first** (`raf = requestAnimationFrame(frame)`). This also lets `stop()` work when it is called during a frame.
- `frame()` keeps the time bookkeeping (`raw`, `dt`, `last`, `uiT` / `uiTick`). The rest of the current body (pose → skeleton → reps → sims → render → overlay) moves unchanged into `step(now, raw, dt)`, which runs in `try/catch`.
- Each `onFrame` / `onTick` subscriber runs in its own `try/catch`, so one broken card cannot stop the others or the `live` mirror.
- `report(where, e)` → `console.error('[engine] <where> failed', e)`, at most once every 2 s (a broken frame throws every frame).

### 2. Release the stage (`render/stage.js`, `engine/engine.js`, `components/StageView.vue`)
- `createStage` gets `dispose()`: it sets `disposed = true`, then calls `renderer.dispose()` and `renderer.forceContextLoss()`. Losing the context frees every GPU resource; the JS objects are garbage-collected with the stage. `refresh()` returns early once disposed, because model loads still in flight end in it.
- Engine `detach()`: `S.stage?.dispose()`, `S.stage = null`, `overlay = null`. `attach()` calls `detach()` first, so a second attach never leaks.
- The look carries over to the next stage:
  - the engine remembers the colour (`setColor` stores it; `attach` applies it when one was set);
  - `attach` re-applies `S.mode` (read **before** `createStage`, whose constructor fires `onMode('particle')`);
  - `setMode` with no stage just sets `S.mode` / `S.dark`, because the drawer stays open across pages;
  - the body is already kept.
- `StageView` `onBeforeUnmount`: disconnect the ResizeObserver, then `engine.detach()`.

### 3. Store → engine sync in one place (`App.vue`, components)
- `App.vue` replaces the long `engine.setX(...)` line with watchers. Components only change the store.
  - `immediate`, because the engine needs the saved value at startup (same order as today): `camTune` (deep), `camHands`, `camModel`, `fitLenient`, `body`.
  - Not immediate: `camView`, which `provideEngine` already passes to `createEngine`.
  - Not immediate: `color`, which is not persisted and starts as the stage default. Applying `#1D231E` at startup would change the ring and lit tones.
- Components stop calling the engine:
  - `CameraTuning.vue`: `apply` / `setModel` / `setLenient` / `setHands` only write the store. Drop `useEngine` if it becomes unused.
  - `DisplayOptions.vue`: `pickBody` / `pickColor` only write the store.
  - `TopBar.vue`: `pickCamView` only writes the store.
- These stay direct engine calls, because they are commands, not saved state: view presets (`BottomBar.pickView`, since pressing the same preset again must re-aim), play / speed / action, source, mirror, look mode.
- `opts` / `profile` stay shared objects read every frame. Unchanged.
