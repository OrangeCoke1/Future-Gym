# 未来健身 2126 · 动作识别原型

网页版的健身动作识别 + 3D 小人动画。主题是「100 年后的健身」。本文件是功能说明：每项功能怎么做、怎么算，以及对应的代码名字。只有中文。

## 启动

这是一个 Vue 3（JavaScript）+ Vite 项目，页面要先构建再打开。页面必须通过 `http://localhost` 打开，**不要直接双击 `index.html` 或 `dist/index.html`**：摄像头和识别模型在 `file://` 下都无法加载。

### 开发（需要 Node.js 22.13 以上，或 24 以上）

在本文件夹里运行：

```
npm install        # 第一次
npm run dev        # 开发服务器，http://localhost:8000/#/，改代码后页面自动刷新
npm run build      # 构建到 dist/
npm run preview    # 在 http://localhost:8000 预览 dist/
npm run lint       # ESLint
npm test           # 单元测试（Vitest）
```

Node.js 版本不够时，`npm install` 会直接报错并写出需要的版本（`package.json` 的 `engines`，`.npmrc` 里开了 `engine-strict`）。`.nvmrc` 写的是 22。

端口固定为 8000（`poster/bake-figure-a.ps1` 依赖这个端口），被占用时会直接报错，而不是换一个端口。页面地址带 `#/`（如 `http://localhost:8000/#/`），因为 `serve.ps1` 这类静态服务器不会把其他路径退回 `index.html`，用 `#` 后面的部分区分页面，刷新也不会 404。

推到 GitHub 的 `main` 和每个 PR 都会自动跑一遍安装、lint、测试和构建（`.github/workflows/ci.yml`）。

### Windows 双击运行

双击 `start.bat`。它先运行 `build-if-stale.ps1`：没有 `dist/`，或者 `src/`、`public/`、`poster/`、`index.html`、`vite.config.js`、`package.json`、`package-lock.json` 里有文件比 `dist/` 新（`git pull` 改过的文件时间就是拉取的时间），就重新构建；只有 `package-lock.json` 变了才运行 `npm ci` 安装依赖，所以依赖没变的电脑不需要联网。然后用 `serve.ps1` 启动本地服务器并自动打开 `http://localhost:8000`。关掉弹出的黑色窗口，或在窗口里按 `Ctrl+C`，服务器就停了。

- 没装 Node.js、安装失败（比如离线）或构建失败时，有旧的 `dist/` 就提示一句并继续打开旧版本，没有就说明怎么办。
- **没有 Node.js 的电脑**：在装了 Node.js 的电脑上运行一次 `npm run build`，把生成的 `dist/` 文件夹拷到这台电脑的本文件夹里，再双击 `start.bat`。`dist/` 不提交到 git。

也可以手动运行（`-Root` 默认是 `dist`）：

```
powershell -ExecutionPolicy Bypass -File serve.ps1 -Open
```

端口被占用时换一个：`powershell -ExecutionPolicy Bypass -File serve.ps1 -Port 8080 -Open`

### 浏览器

用新版 Chrome 或 Edge。首次点「摄像头」时浏览器会询问摄像头权限，需要允许。

主循环每帧做的事出错时（包括某张卡片的每帧回调出错），会在控制台打一条 `[engine] … failed`（同样的错误最多每 2 秒一条），下一帧照常运行，页面不会整个卡住。训练舞台卸载时会释放 WebGL 上下文（`engine.detach()`、`stage.dispose()`），回来时重新创建，外观、颜色和人体模型保持不变。

## 胶囊大厅

打开 `#/` 播放 4.6 秒开场。横置胶囊的圆门先弹出再向两侧滑开，镜头穿过门内灯光，进入鼠尾草绿与象牙白的健身舱。点击画面、按键或用「跳过」可立即进入大厅。系统启用减少动态效果时直接显示大厅，选站后立即导航。同一次访问内返回大厅会跳过开场，刷新后重播。

- 舱内采用嵌入式环灯和灯槽、蓝灰色全景窗及深色仪表玻璃。跑台摆在窗前，拉索力量架与训练椅在右侧，训练垫在前方，哑铃收纳和演示体征屏在左侧。拖动可环顾大厅。
- 点击器械、右墙图标或底部按钮进入对应训练，自动选中默认动作。悬停或以 Tab 键聚焦入口会点亮对应灯带并显示名称与动作，按 Enter 进入训练。窄屏保留底部的四个入口。
- 展会直达 `#/training`。指定动作可用 `#/training?act=jog`，`TrainingView` 只接受 `ACT` 中有效的单个动作键。
- 宽屏且设备支持 HDR 时使用高画质，启用环境反射、实时阴影、轻微泛光和体征屏上的点云人形。`post.js` 在线性 HDR 空间混合泛光，最后统一做 ACES 色调映射和 sRGB 输出。窄屏、低内存或首两秒平均帧时超过 28 ms 时降低画质，保留接触阴影和体征屏上的人形轮廓。
- `STATIONS` 定义有氧跑台（`jog`）、深蹲架（`squat`）、哑铃区（`curl`）和体能垫（`jacks`）。`phaseAt` 驱动开场，`createLobby` 负责画面、选站和 WebGL 资源回收，`LobbyHud` 显示三语入口并通过模板引用定位标签。
- 大厅暂停训练引擎。离开训练页时释放摄像头，回到训练页时恢复已选中的摄像头模式。大厅先释放自己的 WebGL，再恢复训练引擎。无 WebGL 时仍可通过 CSS 开场后的四个按钮进入。

## 使用

- **来源**：「演示」播放内置的 12 个示例动作，动作在底栏手动选择；「摄像头」用 MediaPipe 识别真人。摄像头模式下，深蹲、哑铃弯举 / 推举、原地慢跑由摄像头组的规则（`FIT`）自动识别：识别到哪个动作就自动切换底栏的动作按钮并计数；其他动作（走路、弓步、开合跳等）要手动选择，在「实时跟随」下按原来的规则计数。
- **界面**：电脑上所有内容在一屏内显示，不需要滚动。中间是舞台，次数在舞台左下角，舞台上方是动作名、强度、节奏、时长和发力肌群；舞台右下角是关节角度刻度尺；左侧是三层拼贴：正方形的重心与平衡、扁条的水分（横放的水瓶）、并排的出汗和关节负荷两个小块；右侧是心率、能量和体征；底部选动作和视角。窗口宽度小于 860px（手机）时改为上下滚动。
- **水瓶**：横放，水量 =（今日手动记录的饮水量 − 模拟的出汗量）÷ 2000 ml，瓶身上四条刻度是 500 / 1000 / 1500 / 2000 ml。大数字是已记录的饮水量，「余」是减掉出汗后的量；「撤销」撤回最近一次记录，鼠标悬停能看到是哪一次。
- **出汗**：蓝色小块，显示累计出汗量和当前速度（ml/时）。正在出汗时三颗汗珠循环滴落，越快滴得越快，标题变成「出汗中」。
- **关节角度**：小人关节上是一条细弧和角度数字。舞台右下角是半圆量角器（0° 在左、180° 在右）：橙色弧段是当前动作的计数区间，指针是被追踪一侧的角度，空心圈是身体另一侧同一关节的角度，可以看左右是否对称。
- **调整卡片大小**：卡片之间的空隙都是拖动手柄，鼠标移上去会出现一条短线。可以拖的有：左栏和舞台之间、舞台和右栏之间（改列宽）；左栏三层之间、出汗和关节负荷之间、心率和能量消耗之间（改相邻两张卡片的大小）。也可以用 Tab 选中手柄后按方向键。卡片里的图会跟着卡片大小自适应。布局保存在本机浏览器里（`stick.layout`），面板里的「重置布局」恢复默认（摄像头浮窗也一起复位）。手机宽度下没有这个功能。
- **面板**：右上角「面板」里是次要内容：显示（小人的显示方式、人体模型、光影 / 轮廓 / 肌群 / 血氧 / 角度 / 关键点开关、重置布局、小人颜色）、摄像头跟随（见下）、个人资料、本次训练、数据说明。按 Esc 或点空白处关闭。
- **语言**：右上角切换中文 / 日本語 / English，选择保存在本机浏览器里。翻译表在 `src/i18n/messages.js` 里的 `I18N`，以中文原文为键；缺翻译时显示中文。本说明文件只有中文。
- **粒子全息**（默认）：小人是一个完整的人体粒子云（约两万二千个点，取自人体模型表面：约七成贴着皮肤，两成填在皮下，一成浮在体外形成一圈散逸光晕）。外观是细密的冰蓝闪光：比身体中心更靠近镜头的点偏白、更亮，靠后的点渐变成深蓝，所以看起来有体积；亮度保持稳定，不闪烁。只在打开页面或切换到粒子模式时，粒子先散成一团缓慢旋转的球形云，再陆续飞回各自的位置组成人形（约 2.4 秒，代码里的 `uForm`、`reform`）；切换动作时不会再散开。粒子在站立姿势下生成一次，之后通过蒙皮跟着骨架变形：每个点跟随最近的骨头，关节附近的点在相邻两段骨头之间过渡，所以肩、髋、肘、膝不会断开，跑步时四肢也不会互相穿插（代码里的 `bodyD`、`skinOf`、`skin`）。换成 Xbot / Michelle 时，粒子取自那个模型的表面（`makeBody`、`use`）。叠加的层（全部是概念模拟）：
  - 肌肉：用力的肌群偏橙色（只变颜色，不变亮）；
  - 血氧：每段肢体一条动脉（鲜红，血氧越低越暗）和一条静脉（偏紫，肌氧越低越蓝），粒子沿血管流动，心率越高流得越快；
  - 心脏：胸口左侧的一团红色粒子，按心率「咚—哒」跳动。
  平台上方还有约三千个漂浮粒子，越靠近人站的位置越密；它们固定在场景里自己缓慢上升、摇摆，不跟着小人动。这个模式下舞台底色变成接近纯黑，舞台上的文字和刻度跟着变成浅色。面板「显示」里可以关掉「血氧」，或切回「实体」。
- **体表热量**（舞台左侧，模拟）：正面摊开的人体热成像图，用「铁红」配色（深紫 → 品红 → 橙 → 黄 → 白，下方色条从冷到热，不标具体温度）。头和躯干天然更暖、手脚最凉；正在发力的肌群会变热，停下后热量几秒内慢慢退；核心体温升高时整体变暖（代码里的 `THERM`、`drawTherm`）。人形外轮廓是照一张正面人体解剖参考图描的一整条曲线（`OUTLINE_R`，右半边，左半边镜像），头、颈、斜方肌、三角肌、胸腰、髋、四肢和手脚的比例都按参考图。舞台高度不足约 470 像素时自动隐藏，免得和动作名、计数重叠。
- **数字刷新**：计数增加时不再弹跳、不再冒出「+1」。发力肌群的百分比和进度条、疲劳细线、关节负荷的倍数和进度条、重心比例每帧更新，并做了约 0.12 秒的平滑过渡，数字和进度条连续变化而不是跳变；关节角度、朝向、体征等读数仍每 0.25 秒刷新一次。
- **人体模型**（面板 → 显示 → 人体模型，保存为 `stick.body`）：
  - **原版**（默认）：实体和粒子小人都用 `male_body.glb` 这个真实人体网格（约 4.2 万顶点）。它本身没有骨骼，页面加载时自己解析 GLB（不需要额外的加载库），按在网格上量出的关节位置（代码里的 `MJ`）绑到骨架上：每个顶点跟随最近的骨头，并在关节附近的一段过渡带里从上一段骨头渐变到下一段（代码里的 `skinOf`）：髋部只从髋关节往下开始过渡、越靠近中线越少，小腹和裆部留给躯干；肘、膝、颈、踝约 5 厘米。肩部因为 A 字站姿里胸侧和上臂内侧贴在一起，改为沿模型表面扩散计算权重（类似 Pinocchio 的「热扩散」），过渡自然落在腋窝。关节处的两段骨头不是简单平均位置，而是围绕关节点插值旋转（`blend`），所以大角度时像球形关节一样弯，不会塌成「横板」。躯干可以扭转：髋部高度跟随骨盆朝向、胸口高度跟随肩部朝向，中间逐点插值，所以走路、慢跑、高抬腿时肩和骨盆会反向转动，腿从骨盆上长出来；这些动作还加了上下起伏、左右重心摆动和轻微侧倾（`trunkH`、`D.pelF`、`gait`）。每帧在 CPU 上变形。手臂上举时肩会跟着抬起（肩胛联动，约 30° 以上开始，举过头时肩峰抬高约 5 厘米），肩周的斜方肌、三角肌顶部、上胸和上背按距离一起跟上，肩顶不再出现凹口（`girdleW`、`gDel`）。拿哑铃的动作里手会握拳：模型的手没有手指骨骼，所以在静止姿势里把指节以外的手指绕握把卷起、拇指扣过来，生成一个握拳形状，约 0.2 秒内在张开和握拳之间过渡（`makeFist`、`applyFist`，左右手分别计算）。哑铃放在握拳的握把位置，随前臂转动，握把前后方向（对握）（`gripOf`）；关节角度的数字放在关节两侧离躯干和头更远的一侧。骨架各段长度（`B`）也改成了这个模型的比例。
  - 模型来源：“Male Body”，作者 Alexander Antipov，[Sketchfab](https://sketchfab.com/3d-models/male-body-15a422001834483c9750ce6117d59cc1)，[CC BY 4.0](http://creativecommons.org/licenses/by/4.0/) 许可。**这个许可要求署名**，页面「面板 → 数据说明」里已经写了；对外展示或发布时请保留署名。
  - **Xbot、Michelle**：Adobe Mixamo 的带骨骼角色，有手指骨骼。由 `glbSkin.js` 读取，`riggedModel.js` 驱动：每根骨头的朝向来自解出的骨架，手指跟着握拳程度弯曲，打开手部识别时每根手指按识别到的弯曲程度单独弯（`sol.fingers`）；网格用模型自带的权重在 CPU 上蒙皮。它们保持自己的身材比例，所以关节角度叠加层和摩尔纹的标记点用 `stage.mapP()` 移到模型自己的关节上。第一次选择时才下载，下载完成前继续显示当前的身体（`stage.setBody()`）。「面板 → 数据说明」里写了来源；只能在本应用里使用，不能把模型文件单独再分发。
  - 如果模型文件缺失或无法读取，会退回内置的几何体人形（`ANAT`、`bodyD`）和程序生成的粒子，但那套形状是按旧比例做的，和现在的骨架不完全吻合。
  - 动作幅度大时（例如双臂上举），肩和胸附近会有一些拉伸变形，这是简单蒙皮的局限。
- **摩尔纹**（面板「显示 → 小人」的第三个按钮）：和 feralui.dev/sponsor 页面上的 COBE 点阵地球同一个原理。皮肤上是一层约 1 个像素大小、硬边的点阵，点距约 2.3 个屏幕像素（代码里的 `MOIRE_PX`）；这么小的点会和屏幕像素网格互相干涉，产生摩尔纹（这是设计效果）。点阵像地球自转一样一直在缓慢旋转，所以摩尔纹持续流动，小人站着不动也在动；点阵的行围绕胸口弯成螺旋，条纹就会像地球上那样弯成漩涡。朝向镜头的点更亮，边缘有一圈微光，正在发力的肌群点阵变成橙色；关节上有会轻微"呼吸"的白色亮点，胸口的橙色亮点跟着心跳脉动。舞台同样变成暗色。代码里的 `moireMat`、`MU`、`MOIRE_PX`、`Mesh.marks`。纹路和屏幕分辨率有关（地球也一样），截图或录屏缩小后纹路会变，要在实际屏幕上看。
- **小人（实体模式）**：身体是一体成型的。躯干、头、四肢在着色器里作为一个平滑融合的距离场（SDF）绘制，不是拼起来的几何体；关节点仍然来自同一套 3D 骨架。模型加载完成后实体模式改用模型网格。这部分比较吃显卡，帧率过低时会自动降低渲染分辨率。
- **本次训练**：切换动作或切换来源时，上一个动作完成的次数会记到面板的记录里（刷新页面后清空）。
- **饮水记录、个人资料**：保存在本机浏览器的 localStorage 里，换机器或换浏览器不会带过去。

## 摄像头模式

- **两种显示方式**（顶栏的「实时跟随 / 动作复现」，选择会被记住，`stick.camView`）：
  - **实时跟随**：小人直接跟着真人的关键点动（见下方「怎么跟随」）；
  - **动作复现**：小人不直接跟关键点，而是用演示动画把识别到的动作做一遍。按一个关节角度计数的动作（深蹲、弯举、推举、侧平举），在看得到人时按真人当前的关节角度找到动画里对应的进度，人蹲多深小人就蹲多深（`phaseSync.js`）；其他动作是真人每完成一次，小人就完整做一次（慢跑每步半个周期），真人比小人快时小人会加速追上，最多落后约 3 次。没有识别到动作时小人站着待机，动作结束、回放做完后回到站立。
- **摄像头浮窗**：画面和识别到的关键点显示在一个浮在页面上的窗口里，第一次出现在舞台右下角（约舞台宽度的 45%，320–480 px）。拖标题栏移动，可以拖到页面任何位置；拖四个角调整大小，最大到整个浏览器窗口；双击标题栏或点大小按钮在「小 → 大（窗口宽度的一半）→ 能放下的最大」之间切换；Tab 选中标题栏后方向键移动、Shift+方向键调整大小。位置和大小保存在本机（`stick.camWin`），「重置布局」一并复位。打开手部识别时标题栏显示识别到的手势。
- **怎么跟随**（`pose/camera.js`）：
  - 关键点 → 骨架时保留小人自己的骨长。横向和纵向位置主要取自画面里的 2D 关键点（按躯干长度换算成米），深度取自 MediaPipe 的 3D 世界坐标（它整体会偏几度）（`fuse2d`）。
  - 画面里看得到的关节，即使 MediaPipe 给的可见度掉下去（比如深蹲到底时的膝盖和脚踝）也算看得到（`effVis`）。
  - 每个坐标轴单独用 One Euro 滤波；深度和可见度低的关节平滑得更强。身体朝向做了低通，转身小于 1.5° 时不跟（站着不晃）。
  - **去倾斜**：摄像头放歪时整个小人会跟着歪。程序在人站直、或腿不在画面里但保持不动时测出人的竖直方向，慢慢平均，再把它转回正上方。
  - **预测**：摄像头和识别本身有延迟，所以对置信度够高、正在移动（超过约 0.15 m/s）的关节按速度往前外推，最多 150 ms，静止时不外推以免放大抖动（`camPredict`）。腿比手臂反应更快、提前量更大（`LEG_KB`、`LEG_LEAD`），并且预测不会超出这个人最近几次蹲起的膝角范围（`repRange`）。
  - **腿**：髋前后 −30°…125°、内外 −20°…50°，膝最多弯 150°，脚尖和身体朝向最多差 45°；按腿的置信度在站姿和跟踪之间过渡。
  - 哑铃只在正在计数哑铃动作时才出现在手里。
- **面板 → 摄像头跟随**（改动立即生效并保存）：
  - **预设和滑块**（`stick.camTune`，`camTune.js`）：稳定（0.8 / 3 / 0）、平衡（默认，1.5 / 6 / 60）、跟手（3 / 12 / 120）；三个滑块分别是防抖（One Euro 静止时的截止频率 `minCut`，0.5–5 Hz，越小越稳）、速度响应（`beta`，0–20，越大动起来越跟手）、预测提前量（`lead`，0–150 ms）；「恢复默认」回到平衡。控制台里 `stickman.setCamLead(ms)` 可以临时试一个提前量，不保存。
  - **识别精度**（`stick.camModel`）：高精度（默认，`pose_landmarker_heavy`，四肢位置更准，电脑慢时帧率会降低）/ 标准（`pose_landmarker_full`，更快）。
  - **深蹲识别**（`stick.fitLenient`）：宽松（默认，给展会上动作不标准的参观者）/ 标准（摄像头组的原始规则，要蹲到大腿接近水平、全身关键点都清楚）。宽松是 `fit.js` 里唯一的本地改动（`LEN`）：入镜判断把在画面内、可见度不低于 0.1 的点都算看得到（`effVis`）；深蹲除了原规则，髋部比站立时向膝盖降低 0.1 个躯干长度、并且两侧膝盖都比这个人自己站直时（最近 5 秒里最直的角度）弯下 15° 以上，也算蹲下；两侧膝盖都回到离站直 12° 以内、并且距离蹲下至少 0.6 秒，算完成一次。用 8 个人的录像校准过：宽松 8 个人全对，标准 2 个人对（`tools/count-bench.mjs` 可以重测）。
  - **手部识别**（`stick.camHands`，默认关）：在同一帧上跑 Hand Landmarker（打开时摄像头改为 1280×720，因为全身入镜时手指很小），按姿态的手腕把识别到的手分到左右，驱动小人对应那只手的握拳和手腕转动，并识别几个手势：握拳、张开、比 V、点赞、指（`hands.js`）。原版人体模型没有手指骨骼，只能整手握拳；Xbot 和 Michelle 会弯每根手指。比较吃性能。
  - **腿部**（`legs`）：正常（全身都跟着动，看不到腿时腿跟着上身一起倾斜）/ 自动（默认，看不到下半身时腿和骨盆站着不动，只有腰以上跟着动，`D.pelU`）/ 固定站姿（腿和骨盆一直站着，只有腰以上跟着动）。

## 数据来源标签

| 标签 | 含义 |
| --- | --- |
| 估算 | 按动作强度（MET）或心率公式（Keytel 等，2005）推算，不是测量值 |
| 实测 | 来自已连接的心率设备；超过 5 秒没有新读数就退回估算 |
| 手动记录 | 由用户自己输入 |
| 模拟 | 2126 概念演示，不是任何传感器的读数（见下） |

### 「模拟」的内容

主题是 100 年后的健身，所以加了一层现在的设备做不到实时测量的身体数据。它们全部由程序按运动强度推演，只为展示概念：

- **发力肌群**：每个动作对应一组肌群和强度（代码里的 `MUS` 表），小人身上相应部位会变成橙色，深浅跟着动作幅度变化；舞台右上角列出百分比。面板里的「肌群」开关可以关掉。
- **体征**：血氧、呼吸频率、核心体温、血乳酸、肌氧、心率变异，以及左侧单独一块的出汗量。由心率和肌肉用力程度驱动（代码里的 `updateBio`），心率来自实测设备时它们仍然是模拟值。
- **水分余量和出汗动画**：水瓶的水位 = 手动记录的饮水量 − 模拟的出汗量，所以会随运动慢慢下降，喝水后回升；瓶子旁的「余」是同一个数。出汗速度按真实量级算（静息约 150 ml/小时，高强度约 1 升/小时），所以几分钟内水位变化很小。出汗速度体现在左侧「出汗」卡片的水滴和汗珠动画上，小人身上不显示汗滴。
- **累计疲劳与恢复预测**：每个肌群被用到时疲劳上涨、平时缓慢回落（发力肌群每行下面的黑色细线）；「预计恢复 约 N 小时」由最疲劳的肌群和平均疲劳推出。
- **关节负荷**：膝、髋、腰椎承受的体重倍数，由关节弯曲角度和躯干前倾角度推演，跑跳类动作另加冲击项（代码里的 `updateLoad`）。

### 「骨架计算」的内容

- **重心与平衡**：俯视图，身体朝上。黑色短条是两只脚（抬起的那只变淡），橙点是身体重心在地面上的落点，下面是左右脚各承担的比例。重心由 3D 骨架各段的中点按人体质量分布加权算出（代码里的 `MASS` 和 `drawBal`），接上摄像头后反映的是真实姿态；演示模式下骨架来自示例动作。

## 接入心率设备（蓝牙部分尚未实现）

页面暴露了一个入口，每次拿到读数时调用即可，其他不用改：

```js
stickman.setHeartRate(bpm)   // bpm 为数字；传 null 表示断开
```

收到读数后心率卡片显示「实测」，能量消耗改用心率公式估算。

没有设备时可以在浏览器控制台（F12）里模拟：

```js
hrTest = setInterval(() => stickman.setHeartRate(140), 1000)   // 开始
clearInterval(hrTest)                                          // 停止，5 秒后退回估算
```

## 已知情况

- **摄像头动作识别用的是摄像头组（`media-pipe-practice-main`）校准好的规则**：深蹲、哑铃弯举 / 推举、原地慢跑，阈值与流程和他们的 `apps/web/src/` 一致（代码里的 `FIT`，逐行移植自他们的 TypeScript；他们改规则时这里要同步改）。只在全身入镜时识别（宽松模式下画面内的点都算入镜）。移植时用他们录制的真人视频冒充摄像头测过（帧率约 27–30 fps）：深蹲 13 次、弯举 16 次与他们的结果一致；推举 14 次（他们 15 次，视频一开头的第一次在入镜确认前做完了）；慢跑 67–77 步（他们 81 步，受帧率影响）；走动 / 转身 / 挥手的负样本没有误识别。帧率明显偏低时（例如浏览器窗口在后台）会漏计。
- **所有摄像头计数都只用录制或合成的视频测过，还没用真实摄像头测过。** 单元测试（`test/fit.test.js`）用合成关键点固定了现在的深蹲计数（标准规则只数深蹲，宽松规则浅蹲也数），能防止不小心改坏，但证明不了和摄像头组最新的代码一致（他们的代码不在这个仓库里）。
- 摄像头组的识别覆盖不到的动作（走路、弓步、开合跳等），在「实时跟随」下仍按原来的规则计数。
- 一屏布局在窗口高度约 760px 以上时最舒展；更矮时左侧的正方形会被压扁、两个小块里的图会缩小。手机宽度（小于 860px）下改为上下滚动，并且不显示舞台右下角的关节角度刻度尺；这个布局在最后几轮改动后没有重新检查过。
- 小人身体用着色器逐像素绘制，比较吃显卡；帧率过低时会自动降低渲染分辨率，但没有在低配机器上实测过。高精度识别模型和手部识别也会占不少性能。
- 摄像头模式下小人始终贴地，不体现跳起的高度（MediaPipe 的 world 坐标以髋部为原点）。
- 摄像头模式下，挥手、弓步、开合跳用的是基于关节位置的规则（演示模式是按时间周期计数）；计步的左右脚高度差阈值也比演示模式宽。
- 原版人体模型没有手指骨骼，手部识别时只能整只手握拳或张开；要看每根手指弯曲，请换成 Xbot 或 Michelle。
